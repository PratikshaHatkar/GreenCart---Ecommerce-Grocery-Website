# Database Changes

## 1. User Schema

Instead of only consumers and a hardcoded seller, create one `User` model with roles.

```javascript
{
    name,
    email,
    password,
    phone,
    role: {
        type: String,
        enum: ["consumer", "farmer", "admin"],
        default: "consumer"
    },
    address,
    createdAt
}
```

Every farmer is just another user whose role is `"farmer"`.

---

## 2. Product Schema

This is the biggest change.

Current

```javascript
{
    name,
    description,
    price,
    image
}
```

New

```javascript
{
    name,
    description,
    category,
    price,
    quantity,
    image,
    farmerId: {
        type: mongoose.Schema.Types.ObjectId,
        ref: "User"
    }
}
```

Now every product belongs to a farmer.

Example

```
Farmer A
    Tomato
    Potato

Farmer B
    Mango
    Onion
```

MongoDB

```
Product

{
   name: "Tomato",

   name: "Mango",

}
```

## My recommendation

Since you've already built **GreenCart** with JWT, Razorpay, Cloudinary, and a shopping cart, don't create a separate Farmer model. Use a **single `User` model** with a `role` field (`consumer`, `farmer`, `admin`). This is the approach used in most production MERN applications because it avoids duplicate authentication code and makes role-based access control much simpler.

The key changes are:

* ✅ Remove the hardcoded seller credentials from `.env`.
* ✅ Create farmer registration and login.
* ✅ Add a `role` field to the `User` schema.
* ✅ Add `farmerId` to the `Product` schema.
* ✅ Add `consumerId` and `farmerId` to the `Order` schema.
* ✅ Filter products and orders by the logged-in farmer's ID.
* ✅ Allow farmers to add, edit, and delete **only their own** products.

With these changes, your project becomes a true **Farmer–Consumer Marketplace** where hundreds of farmers can use the platform simultaneously, each managing their own products and orders independently.
